# FINDAT x1 | ProATR — Public OpenAI Access through Supabase

This update lets any visitor chat with x1 without creating or logging into a FINDAT account. The browser calls the public Supabase Edge Function `findat-x1-openai`; the OpenAI API key stays only in Supabase Secrets and is never placed in GitHub or browser code.

Signed-in users are still recognized automatically and can use the authenticated quota. Visitors receive a separate anonymous quota based on a one-way browser/network fingerprint. Prompt and response text are not stored in `findat_ai_usage`.

## Replace these GitHub files

Replace the files using the same paths supplied in the replacement package. Do not delete the rest of the repository.

## Deploy the update

### 1. Keep the OpenAI key server-side

Create or rotate an OpenAI project key. Never paste a real OpenAI key into `findat-auth-config.js`, HTML, JavaScript, GitHub, or any other browser-delivered file.

### 2. Apply the updated SQL

Run `FINDAT-X1-OPENAI-API-UPGRADE.sql` in Supabase Dashboard → SQL Editor. It upgrades the existing usage table in place and adds the anonymous quota function; it does not delete existing FINDAT data.

CLI alternative:

```bash
supabase db push
```

### 3. Set Edge Function secrets

```bash
supabase secrets set OPENAI_API_KEY="YOUR_NEW_OPENAI_PROJECT_KEY"
supabase secrets set OPENAI_MODEL="gpt-5-mini"
supabase secrets set OPENAI_REASONING_EFFORT="low"
supabase secrets set OPENAI_MAX_OUTPUT_TOKENS="1400"
supabase secrets set X1_OPENAI_HOURLY_LIMIT="30"
supabase secrets set X1_OPENAI_DAILY_LIMIT="150"
supabase secrets set X1_OPENAI_ANON_HOURLY_LIMIT="10"
supabase secrets set X1_OPENAI_ANON_DAILY_LIMIT="40"
supabase secrets set X1_ANON_HASH_SALT="REPLACE_WITH_A_LONG_RANDOM_SECRET"
supabase secrets set X1_OPENAI_TIMEOUT_MS="55000"
supabase secrets set X1_OPENAI_MAX_REQUEST_BYTES="180000"
```

Hosted Supabase Edge Functions already receive the Supabase project URL and server keys. Never copy a secret/service-role key into browser code.

### 4. Deploy the Edge Function

```bash
supabase functions deploy findat-x1-openai --no-verify-jwt
```

The repository also sets:

```toml
[functions.findat-x1-openai]
verify_jwt = false
```

This only makes the Supabase endpoint reachable without a user JWT. The function itself still applies request-size controls, optional user validation, anonymous fingerprinting, atomic hourly/daily quotas, and server-side OpenAI authentication.

### 5. Verify the database objects

Run `FINDAT-X1-OPENAI-API-VERIFY.sql` in the SQL Editor. Confirm that:

- `user_id` is nullable;
- `client_hash` and `access_type` exist;
- `findat_claim_ai_quota` exists as a security-definer function;
- RLS remains enabled.

### 6. Test without logging in

Open the public website in a private/incognito window, open x1 | ProATR, and ask a question. A successful response should be generated by OpenAI without opening the FINDAT login screen.

Also test a signed-in account. The browser will attach the Supabase user token when available, but login is optional for x1 chat.

## Important behavior

- Normal conversational answers use OpenAI only.
- X1 no longer silently substitutes embedded RAG or local Ollama text when OpenAI fails.
- Browser-side operational controls—workspace navigation, reconciliation execution, transforms, workflow actions, and report controls—remain local because they manipulate the FINDAT interface directly.
- Imported documents are filtered locally; only selected evidence passages are sent to OpenAI.
- OpenAI requests use `store: false`.
