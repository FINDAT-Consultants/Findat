FINDAT ADMIN BOOTSTRAP — ONE TIME ONLY

Recommended method (no administrator password in frontend):

1. Run FINDAT-AUTH-RBAC-POSTGRES-SETUP.sql in Supabase SQL Editor.
2. Deploy the Edge Functions in the supabase/functions folder.
3. Create a long random bootstrap secret and set it only on the server:

   supabase secrets set FINDAT_ADMIN_BOOTSTRAP_SECRET="REPLACE_WITH_A_LONG_RANDOM_SECRET"

4. Deploy the one-time bootstrap function:

   supabase functions deploy findat-bootstrap-admin --no-verify-jwt

5. Call it once from a trusted terminal. Replace every placeholder:

   curl -X POST "https://gmiqvpemuabjueyprwyl.supabase.co/functions/v1/findat-bootstrap-admin" \
     -H "Content-Type: application/json" \
     -H "x-bootstrap-secret: REPLACE_WITH_A_LONG_RANDOM_SECRET" \
     -d '{
       "email":"YOUR_REAL_ADMIN_EMAIL",
       "username":"admin",
       "password":"CHOOSE_A_NEW_STRONG_PASSWORD",
       "firstName":"System",
       "lastName":"Administrator"
     }'

6. Immediately remove or rotate the bootstrap secret after the account is made:

   supabase secrets unset FINDAT_ADMIN_BOOTSTRAP_SECRET

IMPORTANT
- Do not reuse the former prototype password "admin@123". It appeared in old
  frontend code and must be treated as exposed.
- The service-role/secret key remains inside Supabase Edge Functions only.
- The public website receives only the browser-safe publishable key.

Alternative dashboard method:
- Supabase Dashboard -> Authentication -> Users -> Add user.
- Choose the administrator email and a new strong password.
- Then run this in SQL Editor:

  select public.findat_promote_existing_user_to_admin(
    'YOUR_REAL_ADMIN_EMAIL',
    'admin',
    'System',
    'Administrator'
  );
